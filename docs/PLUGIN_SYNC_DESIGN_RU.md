# Синхронизация плагинов Windows

Дата: 2026-11-06. Реализация: beta **0.1.16**. Пользователь выбрал перенос всех плагинов с однократным подтверждением источника для пакетов вне каталога. Разрешение относится к тестовому релизу в существующем GitHub; публикация в Community Directory отдельно не согласована.

## Результат и границы

Режим **Плагины и настройки** переносит пакеты, точные версии, включение и согласованные переносимые поля между Windows-устройствами. На первом ноутбуке выбирается исходный профиль, на втором он принимается. Настройки чистого получателя не публикуются поверх источника до первоначального принятия. После этого изменения передаются в обе стороны. Команды PowerShell для каждого отсутствующего плагина не нужны.

В рабочем BTV_Base обнаружены 16 сторонних плагинов помимо TotalSync. 15 ID присутствовали в официальном каталоге; pdf-annotator отсутствовал. Это не гарантирует доступность каждого установленного релиза. У Zotero Integration найден дополнительный pdfannots2json.exe. Значения авторизации не включались в диагностический вывод, документы или тестовые данные.

Старый механизм 0.1.15 переносил инвентарь и отдельные проекции Calendar/Excalidraw. Он ограничивал Excalidraw веткой 2.29.x, хотя рабочий vault использует 2.25.3. Новый режим включает поля рабочей версии и отключает прежние проекции на устройстве, пока включён.

## Происхождение кода

1. Каталог Obsidian независимо связывает ID с репозиторием. Получатель проверяет точную версию GitHub Release и хеши стандартных файлов. На последнюю доступную версию автоматически не заменяет.
2. Пакеты вне каталога, недоступные точные релизы и дополнительные файлы можно получать из Mail после однократного подтверждения открытого отпечатка ключа источника на получателе. Пользователь копирует отпечаток с самого источника. Доверие сохраняется для будущих подписанных пакетов и может быть отозвано.
3. Ключ ECDSA P-256 хранится в SecretStorage. Подпись связывает ID хранилища, ID устройства, номер редакции и хеши пакетов. Ранее увиденная замена ключа, откат номера или изменение той же редакции останавливают операцию.
4. TotalSync исключён из переноса. Подтверждение кода не разрешает перенос паролей. Подпись не шифрует содержимое облака.

## Согласование изменений

Каждое устройство записывает собственный профиль в plugin-profiles-v1/<device>.json. Перед обновлением сохраняется подписанная редакция в history/<device>/<seq>.json, файлы пакетов лежат в blobs/<sha256>. Канал не использует общий lock, нумерацию ревизий заметок и не меняет их формат. iPhone с 0.1.15 продолжает читать прежний индекс.

Поля пакета, включения и настроек имеют причинные счётчики устройств. Независимые правки разных полей объединяются; разные одновременные значения одного поля требуют выбора. Массивы считаются одним значением. JSON null отличается от удаления поля. Отсутствие плагина на новом устройстве не считается удалением; удаление определяется относительно принятой локальной базы.

Исходящая подписанная редакция сохраняется локально до отправки. После потерянного ответа PUT проверяется содержимое. При повторе недокачанный объект восстанавливается из проверенных локальных байтов, повреждённый собственный указатель — только при совпадении точной сохранённой исходящей редакции с подписанной историей. Другая корректная подписанная редакция с тем же номером не перезаписывается.

Отложенные входящие изменения не считаются локальными правками. Правка пользователем во время ожидания применения остаётся отдельным конкурентным изменением. Перед применением проверяются просмотренный план, локальные файлы и результат выгрузки работающего плагина.

## Настройки

Явные перечни полей подготовлены для текущего набора пользователя. У Remotely Save перечень пуст: подключение к облаку локально, выключенное состояние сохраняется. Для нового обычного поля требуется выбор на источнике и получателе. Фильтр запрещённых имён и значений дополняет перечни, но не заменяет проверку назначения поля пользователем.

Авторизация, машинные пути, курсоры импорта, разрешения запуска команд и неизвестные параметры автоматически не экспортируются. Локальные значения получателя сохраняются. Передаются только названия пропущенных и требующих локальной настройки полей, без значений; интерфейс показывает вход или путь отдельно от результата применения переносимых параметров.

Шаблоны, заметки и рисунки идут обычным каналом содержимого. Для новых дополнительных файлов пакета нужна отдельная поддержка; разрешены стандартные три файла и помощник Zotero. Фоновые импортеры Telegram/VK не получают распределённую блокировку через TotalSync; отдельный плагин можно исключить на устройстве и оставить выключенным.

## Применение и восстановление

Пакет сначала проверяется в памяти. Транзакция сохраняет старые байты, контрольные суммы и две копии журнала внутри локальной папки TotalSync. До записи повторно проверяется установка. Для работающего плагина обновление ждёт **Применить ожидающие изменения**. Изменение только настроек использует onExternalSettingsChange, когда метод доступен; иначе нужна выгрузка и загрузка плагина. Общее приложение не перезапускается.

Адаптер внутреннего менеджера Obsidian проверяет наличие методов. После включения/отключения явно ожидает saveConfig(), поскольку штатные методы могут только запланировать сохранение списка. Затем проверяются версия, хеши, значения и включение. Ошибка установки или неожиданная миграция настроек приводит к откату. Если восстановление прервано, следующая операция показывает необходимость **Восстановить установку**. Неожиданные новые локальные байты сохраняются рядом с резервной копией до отката.

Резервные установки и история пока не очищаются автоматически. Интерфейс произвольного возврата к старой завершённой версии не реализован; откат ошибки и восстановление прерванной транзакции реализованы. Резервные data.json могут содержать авторизацию и не отправляются в облако.

## Проверка и дальнейшая приёмка

Выполнены проверки установки, двусторонних изменений, конфликтов, версий, включения/удаления, доверия, ошибок сети и восстановления. Подробности и ограничения доказательств — в [отчёте](PLUGIN_SYNC_TEST_REPORT_RU.md).

Остаётся приёмка на двух реальных ноутбуках: версии и включение нужных плагинов, Excalidraw в обе стороны, параметр другого плагина, локальная авторизация и пути. [Инструкция](COMMUNITY_PLUGINS_RU.md) использует существующий BTV_Base. Стационарный ПК и ручной тест отсутствия сети отложены пользователем.

При проектировании использованы [официальный каталог](https://github.com/obsidianmd/obsidian-releases/blob/master/community-plugins.json), [политика Obsidian](https://docs.obsidian.md/community-directory/developer-policies), локальные типы Obsidian 1.14.4 и проверка реализации менеджера установленного Obsidian 1.15.0. Последняя является чтением реализации, а не испытанием в живом рабочем vault.
