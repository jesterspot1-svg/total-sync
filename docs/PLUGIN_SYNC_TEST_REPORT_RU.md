# Проверка профилей плагинов — 0.1.18

## Приёмка на ноутбуках 7 ноября 2026

Профиль нового ноутбука опубликован: 16 из 16 сторонних плагинов. Для Outliner 4.10.2 проверена настройка вертикальных линий в обе стороны. После сообщения пользователя об отключении на старом ноутбуке новый ноутбук получил изменение; после обычного применения TotalSync значение `false` подтверждено в файле и работающем экземпляре Outliner, ожидающих изменений не осталось. Другие настройки всех 16 плагинов этим тестом не подтверждены.

Разделы ниже фиксируют предыдущие автоматические проверки. Их ограничения о неизменённых живых плагинах относятся к разработке того этапа; описанная выше отдельная приёмка использовала рабочий Obsidian с разрешения пользователя. Аудит следующего выпуска: [0.2.0](COMMUNITY_RELEASE_AUDIT_RU.md).

## Исправление Outliner в 0.1.18

Проверен установленный Outliner 4.10.2: он сохраняет настройки как `styleLists`, `debug`, `stickCursor`, `betterEnter`, `betterVimO`, `betterTab`, `selectAll`, `listLines`, `listLineAction`, `dnd`. Предыдущий список TotalSync содержал другие имена, поэтому изменения этих полей оставались локальными. Добавлены актуальные имена, старые сохранены для совместимости; служебный `previousRelease` остаётся локальным.

Два новых регрессионных теста воспроизвели ошибку до исправления и прошли после него. Проверена передача `listLines` между одинаковыми уже установленными пакетами в обе стороны, ожидание применения активного плагина, сохранение локального `previousRelease` и отсутствие повторной публикации без изменений.

Локально пройдены TypeScript, ESLint, **109 тестов**, сборка, smoke и security-проверка релиза. Проверки запускались отдельными командами из `npm run check` через доступный Node.js. Реальная проверка на двух ноутбуках выполняется по [инструкции Outliner](OUTLINER_TEST_RU.md); автоматический стенд её не заменяет.

## Исправление подготовки ключа в 0.1.17

7 ноября 2026 пользователь сообщил об ошибке при выборе исходного ноутбука. В 0.1.16 идентификатор закрытого ключа содержал два полных UUID и имел длину 99 символов. Чтение реализации SecretStorage в установленных Obsidian 1.12.7 и 1.15.0 подтвердило максимум 64 символа. Прежний mock этого ограничения не проверял; с добавлением проверки smoke-тест прежней сборки воспроизвёл отказ до появления отпечатка.

0.1.17 использует идентификатор длиной 62 символа, вычисленный из обоих ID. Ранее сохранённый ключ повторно используется; при наличии старой записи переносится без замены ключа. WebDAV-пароль и состояние привязки не изменяются. Отказ подготовки ключа теперь имеет отдельный код `plugin-secret`, а не сообщение о свободном месте.

Локальный `npm run check`: **107 тестов прошли**, включая **41 проверку профилей плагинов**. Добавлены проверки длины, изоляции хранилищ и устройств, постоянства ключа, переноса старой записи, ошибок чтения/сохранения и повторной попытки. Smoke-модель ограничивает ID так же, как Obsidian, и проверяет ошибку хранилища секретов, повтор через «Обновить источники» и появление отпечатка. TypeScript, ESLint, сборка и проверка релиза прошли. Это не подменяет повторную проверку на ноутбуке пользователя.

## Предыдущая проверка 0.1.16

Дата отчёта: 2026-11-07. Локальный результат `npm run check`: **104 теста прошли**, включая **38 новых проверок профилей плагинов**. TypeScript, ESLint, сборка, smoke-проверка загружаемого плагина и проверка состава релизных файлов завершились успешно.

## Граница подтверждения

- Все тестовые данные искусственные. Реальные заметки, токены и `data.json` рабочего хранилища не использовались как тестовые фикстуры и не публиковались.
- Реализация менеджера установленного Obsidian 1.15.0 проверена чтением: наличие методов и необходимость дождаться `saveConfig()`. Живые плагины BTV_Base в ходе разработки не заменялись и не перезагружались.
- GitHub и Mail не использовались стендом как реальные получатели данных пользователя. Каталог проверен фикстурами, WebDAV — локальным HTTP-сервером.
- Нет утверждения, что все сторонние плагины испытаны на двух физических ноутбуках. Такая приёмка выполняется по [инструкции](COMMUNITY_PLUGINS_RU.md).
- Координации фонового импорта Telegram/VK нет в TotalSync. Секреты и состояние импорта локальные; ненужный экземпляр можно исключить из синхронизации и выключить.
- Пакеты с другими вспомогательными файлами, кроме стандартных и `pdfannots2json.exe`, не поддержаны. История пока без автоматической очистки и без интерфейса выбора произвольной старой установки.
- Ручной тест отсутствия сети и стационарный ПК отложены по просьбе пользователя; ошибки передачи проверены автоматически.

Перед публикацией артефакты дополнительно собираются GitHub Actions. Этот документ фиксирует локальную проверку, а не подменяет результат CI или пользовательскую приёмку.
