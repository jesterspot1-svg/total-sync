# Архитектура

    Obsidian Vault API   → content        → Mail Cloud WebDAV
    Vault DataAdapter   → desktop-config → Mail Cloud WebDAV
    Снимок закладок     → shared-state   → Mail Cloud WebDAV

Локально сохраняются UUID устройства, привязка к аккаунту и UUID vault, последняя принятая ревизия и независимые базовые сигнатуры. Пароль хранит SecretStorage. Общий индекс и бинарные объекты размещаются под `TotalSync-beta/vaults/<UUID>/`. Имена оригинальных файлов находятся в индексе, объекты адресуются случайными UUID. Переименование локального vault сохраняет привязку.

Сеанс сначала читает зафиксированную ревизию и сверяет хеши. Клиент, прошедший проверку MOVE с запретом перезаписи, готовит индекс и его SHA-256 в уникальном каталоге `metadata/staging/<UUID>`. MOVE с `Overwrite: F` занимает следующий номер в `metadata/revisions/<номер>`. Если номер уже занят, клиент сверяет новую ревизию и пересчитывает план. После проверки индекса плагин публикует маркер в `metadata/commits/<номер>` через MKCOL. При сбое между MOVE и MKCOL другой клиент может проверить SHA-256, ссылку на родителя и завершить публикацию. Общий каталог `metadata/lock` в этом режиме не используется.

Без подтверждённой поддержки MOVE клиент получает эксклюзивный `metadata/lock` и резервирует ревизию через MKCOL перед записью индекса. Оба режима используют ту же цепочку и формат опубликованных ревизий. Старый резерв без файла `ready` нельзя подтвердить автоматически. Опубликованные изменения можно получать без блокировки.

Если запись метаданных в прежнем режиме вернула тайм-аут, клиент проверяет её результат. Индекс принимается после сверки SHA-256, маркер сверяется с ожидаемым индексом. Отсутствующую запись можно повторить один раз. Каталог блокировки или резерв с неопределённым владельцем требуют ручной проверки. В диагностике указывается этап без имени файла или идентификатора хранилища.

Если план включает отправку как минимум 24 новых файлов без конфликтов, удалений и входящих изменений, клиент публикует порции до 24 операций. Объекты с уникальными UUID передаются по одному и проверяются до захвата блокировки публикации. При тайм-ауте непроверенный файл ждёт повтора. После трёх тайм-аутов подряд клиент сохраняет проверенную часть порции и откладывает остальные отправки. Следующий проход сверяет опубликованные ревизии и локальные файлы.

При сканировании заметок и вложений свежий SHA-256 берётся из памяти, пока совпадают размер и метки времени файла. События Obsidian и истечение 15 минут заставляют перечитать файл. Независимые запросы к метаданным идут параллельно, а до трёх файлов размером до 2 МиБ передаются одновременно. Содержимое проверяется перед отправкой и после получения. После фиксации индекса локальные операции применяются по порядку с повторной проверкой файла перед изменением.

План сравнивает локальное и удалённое состояние с базовой версией. Для Markdown в UTF-8 размером до 512 КиБ сравниваются три версии по строкам. Совместимые правки объединяются. Пересекающиеся правки, отсутствие общей версии или превышение бюджета сравнения требуют разбора на устройстве с неопубликованной правкой. Если версия Markdown превышает 512 КиБ или не декодируется как текст, окно показывает начало расхождения и позволяет сохранить одну версию целиком. Для Markdown в обоих случаях используется исходный файл, а исходные версии попадают в историю перед заменой. Для двоичных вложений остаются конфликтные копии, а для конфигурации спорные версии доступны в истории. Очистка удаляет только объекты за пределами активного индекса и срока хранения.

Windows синхронизирует настройки из перечня, мобильный профиль отключает desktop-канал. Каталог конфигурации берётся из `app.vault.configDir`. Инвентарь показывает ID, версии и состояние плагинов и формирует команды штатного CLI для недостающих. Снимки закладок и перечни плагинов хранятся отдельно от живых конфигураций. Для Excalidraw передаётся проверенная проекция разрешённых полей. Перед применением проекция предыдущих значений сохраняется локально, остальные поля исходного файла остаются на месте.
